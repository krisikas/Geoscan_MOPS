# Демонстрация МОПС без дрона

Дата: 2026-11-05. Цель пользователя: представить планирование, фотографии, результаты ИИ, 3D и имеющиеся видеозаписи; реального полёта не будет. Ниже — оценка по коду и локальным файлам, без запуска сервисов и оборудования.

## Минимальная схема

Для просмотра сохранённых проектов нужны frontend + backend + PostgreSQL + файлы проектов. Для нового планирования дополнительно нужны ai_service и настроенный CLI agy с доступом к модели. MCP, telemetry и дрон для этих действий не нужны.

Просмотр готовой GLB не вызывает Metashape и не требует его лицензии. Но установка текущего backend всё ещё включает Metashape, а импорт API сразу загружает модуль AI с torch, OpenCV, SAHI и их зависимостями. Поэтому режим «только просмотр» пока не отделён от тяжёлого окружения.

## Что уже есть для показа

- Локальный `backend/data` занимает около 2 GB. Есть папки проектов 9, 10, 11, 12; наличие соответствующих записей и владельцев в БД пока не проверено.
- В проектах 9 и 10 есть `model.glb` размером около 55.1 и 30.6 MB. Обе модели содержат геометрию, нормали и цвета вершин (`COLOR_0`), без изображений текстур и материалов. Внешних изображений этим файлам не требуется. Качество отображения не проверено визуально.
- Есть исходные серии, одиночные фотографии и готовые результаты старого AI pipeline. В проекте 10 также есть `orthomosaic.png`.
- Планировщик и 3D-просмотр маршрута не зависят от аппаратного подключения. В интерфейсе есть ползунок просмотра точек.
- Видеофайлы в просмотренном репозитории не найдены; пользователь сообщил, что записи работы у него есть. Встроенного видеоплеера/импорта записей в текущем интерфейсе не обнаружено.

## Подробности, влияющие на сценарий

- `backend/data/` игнорируется Git; PostgreSQL хранится в Docker volume и не копируется с репозиторием. Перенос одних файлов в папку с новым ID не восстанавливает записи, права, чат и маршрут.
- Локальные старые результаты преимущественно лежат в `ai_output` / `metashape_ai_output`; текущий API читает папки с суффиксом модели. Часть старых результатов JPEG может быть уже изображением с нарисованной разметкой, а текущий UI ожидает отдельную PNG-маску с прозрачностью. Нужна проверка формата, простого переименования может быть недостаточно.
- `Environment preset="city"` в `AdvancedModelViewer.jsx` получает HDR из внешнего CDN; Model находится в том же Suspense. Шрифт Inter тоже загружается из Google Fonts; ресурсы 3D-подписей нужно отдельно проверить в офлайн-прогоне.
- GLB в 30–55 MB загружаются целиком через fetch → blob; страница заранее скачивает файлы всех групп, даже не открытых. Для большого проекта вероятны долгая первая загрузка и расход RAM. Статус загрузки 3D минимальный, error boundary для модели не предусмотрен.
- В текущем 3D-просмотрщике нет привязки результатов дефектоскопии к поверхности GLB: маски относятся к 2D-снимкам. Не обещать интерактивную 3D-карту дефектов как уже реализованную.
- Обработка отдельного снимка принимает только `ai_input` и `metashape_input`. Показ и анализ итоговой ортомозаики требуют отдельной подготовки интерфейса/данных; перенос ортомозаики в одиночные фото возможен как явный отдельный шаг.
- На экране миссии `currentStep` после получения плана равен 0, поэтому показывается первая точка; весь маршрут появляется при перемещении ползунка к концу. Автоматического воспроизведения маршрута нет.
- Экран миссии не использует ID из URL для выбора проекта, изначально выбирает первый из списка. Прямая ссылка на нужный демопроект может открыть другой.
- Приветствия и некоторые ошибки записываются в поле `text`, а сообщения выводятся через `content`: на экране возможны пустые сообщения.
- При ошибочном JSON планировщик может вернуть пустые массивы; backend перезаписывает ими сохранённый маршрут. Демопроект с готовым маршрутом лучше хранить отдельно от экспериментов.
- Планировщик не валидирует числа/структуру маршрута. Визуализатор вызывает `.toFixed()` у координат: строка вместо числа может сломать рендер. Для показа важна схема ответа и обработка ошибок.
- Микрофон зависит от поддержки браузера, разрешений и сервиса распознавания; текстовый ввод надёжнее как основной путь.
- `VITE_API_BASE_URL` по умолчанию указывает на localhost. Показ на том же ноутбуке проще; браузер на другом устройстве, удалённый сервер или HTTPS потребуют корректных адресов, CORS, cookie и проксирования SSE. Изменение Vite env требует пересборки production frontend.
- На новом компьютере нужны Python >=3.12, Docker/PostgreSQL, backend env с SECRET_KEY, подходящий Metashape wheel при установке текущего окружения. backend Dockerfile сейчас не согласован с pyproject; полный контейнерный перенос пока не подтверждён.
- Текущий общий JS bundle около 1.52 MB. Сборка frontend успешна; ошибки lint сами по себе её не блокируют, но показывают отсутствие чистой проверки качества. Они ниже по приоритету, чем видимость данных и автономность демонстрации.

## Предлагаемый сценарий выступления

1. Открыть подготовленный проект и объяснить задачу обследования.
2. Показать сохранённый маршрут вокруг здания, пролистать точки, углы камеры и yaw. Затем показать новый запрос планировщику, если сервис доступен; сохранить готовый проект как резерв.
3. Показать запись реального полёта, явно подписанную как архивную.
4. Открыть исходные RGB/тепловые кадры, проверенные маски YOLO/CrackSAM и увеличение дефектов.
5. Показать готовую ортомозаику и вращаемую GLB; объяснить связь этапов. Полный пересчёт фотограмметрии подготовить заранее.

Критерий готовности: после перезагрузки ноутбука и с отключённым интернетом доступны вход, нужный проект, сохранённый маршрут, снимки, маски, модель и видео. Новое облачное планирование проверяется отдельно при наличии сети. До выступления прогнать весь сценарий без кеша, проверить проектор/браузер и иметь копию демоданных и локальную запись экрана.
